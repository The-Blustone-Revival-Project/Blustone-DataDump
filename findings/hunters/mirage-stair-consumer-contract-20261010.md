# Mirage stair parser, visuals and balance scale

Original final-version library evidence, 2026-10-10. The replica remains an empty read-only Floor0 lobby; no Mirage floor/enemy/reward data is granted by this work.

`ghidra-mirage-stair-consumers.txt` closes ParseStairInfo G9343b4. The selected `ref_stair` subtree is `{res_prefix:string,res_postfix_list:string[],list:[{grade,balance},...]}`. Both collections are explicitly type2 arrays before rebuilding. `grade` and `balance` are read from each row, not the outer object. Row ordinals are generated one-based in array order; no row ID is read. Model prefix+74, string vector+80/84/88, linked rows+8c/90/94. Each20-byte row stores links0/4, ordinal8, balance+c, grade+10. Scalar conversions accept numeric strings, bool, signed/unsigned integer low32 and truncated double; production values/domain remain missing.

The selected stair balance is material. `native-makestageinst.txt:2753` searches row ordinal against base+44, converts row+c as signed32 to float and multiplies the float literal at G925dd0. `ghidra-mirage-balance-literal.txt` proves word0x38d1b717, IEEE754 value0.00009999999747378752. This is approximately one ten-thousandth: balance10000 gives native float1.0; balance100 gives approximately0.01; a found zero row gives zero. Only a lookup miss uses default1.0. This unit does not recover original difficulty values, and neutral10000 must not be presented as a recovered original row. `mirage-balance-literal-20261010.json` records the decoding and calculation.

`ghidra-mirage-stair-bindings.txt` proves GetStairInfo returns model+74, GetResName returns model+c4. CreateStair Gbf9948 concatenates the prefix string at+74 with the current postfix at+c4; SetBG G93ca44 loads the resulting name as a9-sprite into the BG_STAGE node, retaining its native size/9-sprite ratio. This is a resource name, not a server stair ID. `ghidra-mirage-stair-postfix.txt` proves MakeRandResPostFix G92e868 chooses an index from0 to(vector count−1), then assigns that string to+c4. There is no local empty-vector check in that helper; route/caller admission before invocation remains to be closed. The current empty lobby must not activate that path.

Init/SetGrade use a four-entry string table, constructed at offsets0,+c,+18,+24. Original grade0 string is empty (literal pointer target G1d62ab4 begins NUL); grade1 B, grade2 S, grade3 G. Both Init and SetGrade index by supplied reward type without a local bounds check. Supported table positions are0..3; this does not establish which original stairs used each grade. Box animations are MS_RW_ plus the grade suffix, opened sprites add8, lock sprites use MIRAGE_ plus suffix. `ghidra-mirage-stair-draw-strings.txt` binds those literals to exact ADD sites. Referenced sprites/animations must be matched to actual owning packs and UI before any nonempty deployment.

CalcState G93b28c compares candidate ordinal with current base+44: above→4; below→1; equal/base state1→2; equal/base state2→3; otherwise1. CreateStair maps returned state1 CLEARED,2 FIGHTABLE,3 RECEIVABLE,4 LOCKED, default STATE_NONE. Init computes the same branches. Its old void decompilation is misleading: `ghidra-mirage-stair-init-return-asm.txt` records the status in r4 and returns r0=r4 at93adfc. Source-level symbolic enum names do not establish server transition transactions.

Historical original help/code1441 corroborates HP carryover and3/6/9 battles by floor bands, but final-version floor assignment, enemy groups, balance/grade rows, reward amounts, revive prices, rotating heroes, daily reset and its timezone remain unrecovered. The original MIRAGE pack supplies image material, not those rows. No guessed nonempty references, grants, new weekly/daily policy, APK patch or live Mirage input was made. Next substantive seam is the actual RequestNextFloor callback and caller gates before introducing a proven nonempty stair selector.

## GetNextFloor callback boundary

`ghidra-mirage-nextfloor-builder.txt` and its exact-string export prove RequestNextFloor G9322d8 posts `/mirage/GetNextFloor` with the five authentication fields app_code/app_ver/market/pvid/otp; no floor/grade/balance selection field was found in this builder. The wrapper primary guards are G2157638 and G2157678, derived from the PC-relative words and recorded in callback-slots/vptrs exports. Their virtual+18 targets are original odd Thumb pointers G938735/G938a61; bounded temporary Thumb exports at even938734/938a60 were discarded from the read-only project afterward.

The first wrapper stages the returned JSON. The second checks GetResultCode1 and presence of ret_data, reads exactly ret_data.next_floor, and delegates to the captured callback with that uint result. Failure, absent subtree or unsupported type defaults to0. Boolean and integer paths read the low value; string/double path converts through a positive-value guard. This native permissiveness is not validation of an original floor domain. The callback itself does not call Parse_InstBase/ParseStairInfo/Parse_InstEnemy/MakeRandResPostFix or directly write those models; delegated caller effects remain unclosed. Auth-only request and scalar result therefore do not authorize generating a floor or advancing state. Caller/callback admission and subsequent data refresh are the next target.
