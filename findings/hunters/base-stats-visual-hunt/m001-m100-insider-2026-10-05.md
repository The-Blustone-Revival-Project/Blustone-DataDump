### 1.3 Reuse proof — thumb-level decoupling (CB1201 actor rows reused in CB1401)

Verified from disk this session by joining the STAT table against both combat
files:

- `CB1401` does **not** define its own M041/M042 mob rows. Its first four
  right-side placements reference the literal actor ids `CB1201_M1`
  (`res_id` M041) and `CB1201_M3` (`res_id` M042) — the same ids defined for
  `CB1201`.
- In `CB1201` those actors are thumbed L10/r5/h2; in `CB1401` the *same actor
  ids* are thumbed L15/r5/h2. The STAT table holds exactly one row per actor
  id, so one fixed tuning serves two displayed levels.
- This is the cleanest local proof that the combat thumb
  `{level, rank, hyper}` is display/progression context for a scripted fight,
  not an input to a base-stat formula: the displayed level moved 10 → 15 while
  the referenced STAT row did not change.
- Contrast with M100 itself, which goes the other way: two displayed levels
  (L10 boss vs L15 boss) backed by **two distinct** STAT rows
  (`CB1201_BOSS` vs `CB1401_BOSS`) with disagreeing tuning — per-appearance
  scripting, not one base tuple. Full numerals for both M100 rows are impure
  material and appear only in §2.

### 2.4 M100 A→B delta (impure, do not model as growth)

- HP +25% (16000 → 20000), ATK +14% (7000 → 8000), DEF *falls* 300 → 280 as
  thumb level rises 10 → 15 at constant rank 5 / hyper 2.
- Falling DEF with rising level rules out any monotone level-scaling law on
  this pair; treat as two independent scripted boss tunings.
- Secondary drift: crt_dmg 200 → 250, hp_regen 100 → 150; block line
  (30.00/30), penetration (0.00), attr_enhance (0), attr_resist (0), spd (0)
  unchanged.
- Never join these HP values to any video bar token (identity,
  chapter/difficulty, and full-vs-current semantics all unproved on the video
  side). Never collapse A+B into one tuple without stating the rule — and no
  collapse rule is endorsed here.
