# Dec-2017 hero roster reconstruction (2026-10-05)

**Goal:** which catalog heroes provably existed by Dec 2017 (ApkHere tail
`1.2.1.1`, 2017-12-21)?

**Result: the roster was catalog IDs `001`-`031` -- 30 named hunters plus one
Tyltyl variant row (`026`).** 27 of those are proved by two stamped Sept-2017
CDN manifests; the remaining four (`001` Lantern, `003` Nene, `009` Captain,
`010` Vincent) are the exact complement of that CDN set and are proved
APK-bundled instead, witnessed by the held `1.4.4.1` APK. The upper bound at
`031` is supported by three independent lines and is an **inference**, not a
primary record. **No base stats recovered; strict coverage unchanged (heroes
1/113, monsters 0/22, accessories 1/100).**

**This revises the earlier draft of this file**, which stopped at "27
asset-proved IDs" and left `001`/`003`/`009`/`010` unresolved. Line B closes
that gap.

**Supersedes nothing else.** §1 is pure (stamped manifests, a held APK, dated
release rows, and client-recovered reference fields only). §2 holds every
roster-rating token, rank-up progression token, and release-date anchor as
**impure** rebalance material. No server/APK/seed/emulator/phone/Ghidra/native
operation. No binary downloaded from any mirror. No stat inferred from art.

## 1. Pure: Dec-2017 roster with provenance

### 1.1 What counts as "provably existed" here

Three independent evidence classes, deliberately kept separate so a weak class
cannot borrow a strong class's credit:

| Class | Source | Strength |
|---|---|---|
| **A. Dated shipped-art manifest** | stamped CDN reslist from a 2017 capture | proves the client *shipped art* for that ID |
| **B. Dated shipped-art manifest, other channel** | held APK ZIP, `.jet` manifest | proves the client *shipped art* via a different channel |
| **C. Dated release row** | community-harvested index | proves a *date*, second-hand, no primary record |

Classes A/B prove art shipped; they do **not** prove playability and they do
**not** prove stats. Per the standing server-side conclusion
(`apkhere-gallery-2026-10-05.md` §1.6, `old-apk-2026-10-05.md` §2-§3),
per-entity stat tables live server-side in *every* audited build, pre- and
post-rebalance, so no build of this game can yield a base HP/ATK/DEF row from
art or a reference dump.

**Descriptive columns are stronger than they look.** `name`, `rarity`, `role`,
`element`, `owner_card_id` in the tables below come from
`analysis/catalogue/data/card-catalogue.tsv`, which is **[RECOVERED]** from the
shipped client's own `CHAR_STR_RO` / `SKILL_REF_RO` / `SKILL_TAG_RO` tables
(`analysis/catalogue/INDEX.md` §1.1), not from community metadata. The era
caveat is real but narrow: those tables are from the shipped `2.8.0.1` client,
so a role/element/rarity **could** in principle have been rebalanced later.
Nothing found suggests it was, and the counts are internally consistent.

### 1.2 Line A: Sept-2017 CDN manifests -- 27 hero art packages

Both read locally from the VSFan archive; neither was re-downloaded.

- `analysis/VSFan/Research/Blustone/Extracted Updates/1.1.2.0/reslist_20170904165634.txt`
  - stamp `20170904165634`, **140 packages / 379,438,483 B**
- `analysis/VSFan/Research/Blustone/Extracted Updates/1.1.3.0/reslist_20170908141924.txt`
  - stamp `20170908141924`, **149 packages / 385,496,169 B**

**Re-verified this pass, both files.** The hero main-art set is **byte-identical
across the two stamps** -- 27 packages:

```text
C002 C004 C005 C006 C007 C008 C011 C012 C013 C014 C015 C016 C017 C018 C019
C020 C021 C022 C023 C024 C025 C026 C027 C028 C029 C030 C031
```

Verified absent from both: **`C001`, `C003`, `C009`, `C010`**. The only trace of
the fourth is an effects-only package: `C010_EFT,20170410143516,3207390`.

`C902,20170328234908,408929` is also listed but is **not** a hero package and is
excluded from roster purposes.

Because the C-set is *identical* between the two stamps, **no hero-art package
was added or removed between 2017-09-04 and 2017-09-08** -- a useful null
result in its own right.

### 1.3 Line B: the four missing IDs are APK-bundled -- the union is closed

This is the finding that completes the roster. The four IDs absent from the
Sept-2017 CDN set are exactly `001` Lantern, `003` Nene, `009` Captain,
`010` Vincent -- the game's starter/core hunters. A first-run 2017 client
cannot render its own starters from a CDN package the manifest does not list,
so the art must have shipped inside the APK.

**Two independent witnesses:**

1. `analysis/VSFan/Extracted Assets (2026)/1441 (APK)/` contains C-family
   directories for **exactly** `C001`, `C001_EFT`, `C001_SND`, `C003`,
   `C003_EFT`, `C003_SND`, `C009`, `C009_EFT`, `C009_SND`, `C010` -- and no
   other `C0*` directory. Every other hero pack in the tree comes from the CDN.
2. `old-apk-2026-10-05.md` §2 and §4, from a read-only in-memory ZIP audit of
   the same APK, record "Character packs `C001/C003/C009/C010` (153-192
   resources each)" and the `.jet` manifest with uncompressed sizes
   `C001 2167418`, `C001_EFT 1308526`, `C001_SND 146122`, `C003 1867356`,
   `C003_EFT 1481650`, `C003_SND 74411`, `C009 1998721`, `C009_EFT 1616214`,
   `C009_SND 100983`, `C010 1974843`.

The two channels are **disjoint and complementary**, and the CDN channel's
complement within `001`-`031` is *precisely* the APK channel's contents:

```text
CDN (Sept 2017)  = {002, 004..031}                = 27
APK (1.4.4.1)    = {001, 003, 009, 010}           =  4
                 -------------------------------------
union            = {001 .. 031}                    = 31
```

There is no gap to explain and no leftover to speculate about. **This is the
strongest statement available: the Dec-2017 shipped-art set was exactly catalog
IDs `001`-`031`.**

Honest limit on this line: witness B is dated **2018-08-12** (`1.4.4.1`), not
2017-12-21. The *complementarity* is a strong reason to read it back to 2017,
but strictly it witnesses 2018 packaging. See §1.8 for the one residual gap
this leaves.

### 1.6 Shape of the roster, and a role-completeness cross-check

Computed from the table above (30 named rows):

- **Role:** Offense 9 · Bomber 7 · Defense 8 · Support 6
- **Element:** Lightning 11 · Fire 10 · Ice 9
- **Rarity:** 1-star 11 · 2-star 9 · 3-star 9 · 4-star 1 (Vincent `010` only)

Two observations:

1. **All four roles were populated by Dec 2017**, so the 4-role marketing copy
   on every store listing ("10-taps / 4-role team", `apkhere-gallery-2026-10-05.md`
   §1.2) describes a real Dec-2017 roster, not a later feature.
2. **Lightning leads Fire 11-10 and Ice 9.** Treat this as a weak prior only:
   it rests on community-sourced release *naming*, and a single absent
   2017-dated hero would move it.

Cross-check against the Namu four-role pages (`bahamut-thumb-2026-10-05.md` §5),
whose star-count header is Attacker 1*/2*/3*/4* = 3/3/11/6 (23) · Defender
3/3/9/3 (18) · Bomber 3/2/7/4 (16) · Support 3/3/7/5 (18). Resolving its names
against the catalogue, **every one of the 30 Dec-2017 named heroes appears in
those four lists**, and the lists' 75 slots additionally cover `032`-`098`. That
is an independent confirmation of the `001`-`031` identities and roles from a
different-language, different-date source.

### 1.7 Upper bound: what keeps `032`+ out of the Dec-2017 roster

Three lines, in decreasing strength:

1. **Art (strongest).** The Sept-2017 CDN manifest contains **no** `C032` or
   higher hero package. A playable hunter needs art; nothing `>= 032` shipped.
   The only `C9xx` entry is `C902`, not a hero.
2. **Release dates.** `045` Yuri 9 Feb 2018 is the earliest dated row after the
   `031` block, and Bahamut §5's dates put `054` Dino at 2018-06-29 and `055`
   Apollon at 2018-08-17 (§1.4). Two sources, both post-Dec-2017.
3. **Shape.** `032` Scar is catalogued 2-star Offense Ice -- a role/element/
   rarity combination already well represented inside `001`-`031`, so nothing
   about the ID `032` itself implies a gap.

**This is an inference, stated as one.** It is a strong inference with three
independent legs, but no primary Dec-2017 record was found that says "the roster
ended at `031`".

### 1.8 Brackets that fit, and the one residual gap

Consistent with the reconstruction:

- **2019 JP archive.** `archived-hunter-database-2019.tsv` holds **63 rows**
  whose `catalog_id` values are exactly **`032`-`063`** plus 31 rows covering
  **`001`-`031`** -- i.e. the archive's numeric ID space is **`001`-`063`**
  (62 rows + 1 placeholder), with no `064`-`098` pages and an empty 5-star index
  (`archive-jp-fill-2026-10-05.md`). A `031`-wide roster in Sept-2017 growing to
  `063` by Oct-2019 fits, and the `064`-`098` block dating to 2019-2020 matches
  the dated release rows. These archive rows carry 13 numeric fields but **no
  level or equipment context**, so they crosswalk identity only and earn no
  coverage credit.
- **Replica floor.** The local replica's own progression content tops out inside
  this range (`n_01_01`-`n_01_10` stages, four- to five-role party work), and the
  historical community cap is Lv.30 with 3-star `MAX` -> 4-star advancement.
  Consistent with a 30-hero, 4-role, 1-4 star launch roster.

**Residual gap — the largest remaining uncertainty in this file.** The newest
manifest evidence is **2017-09-08**, but the cutoff target is **2017-12-21**: a
**14-week window with no manifest**. A hero released in Oct/Nov/Dec 2017 would be
invisible to Lines A and B. Line C argues against one existing (`045` is the
first post-`031` date, Feb 2018), but Line C is second-hand. Anyone extending
this work should treat "a `032`-class hero shipped in late 2017" as **open, not
closed**, and should look for an Oct-Dec 2017 manifest or dated announcement
before treating `001`-`031` as final.
**[GAP CLOSED 2026-10-05 per `roster-gaps-2026-10-05.md` — positively, not
null.** That file searched inside the window and found **dated official/community
records for `036` Bear (2017-11-08), `038` Rebecca (2017-11-30) and `034`
(2017-11-03, referring to Oct 2017)**, plus an existence bound for `051` Beckhen

`032`, `033`, `035`, `037`, `039`-`050`, `052`+ still unresolved and not excluded.
The §1.8 request for an Oct-Dec 2017 dated record is therefore satisfied — the
window needed no new manifest, only dated announcements.]

### 2.3 Release-date anchors restated as impure

  order the roster, **never** to date a stat value or to assume a panel's era

  here is the §1.4 exact agreement on Dino/Apollon, which corroborates the axis

  presence: shipped art is not a release announcement.

  crosswalk silently drops them (§1.5 shows how Bahamut §5 resolves both).
