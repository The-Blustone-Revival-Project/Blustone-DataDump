# APK version diff 1.4.4.1 → 2.8.0.1 — version-added content (2026-10-05)

Lane: compare the VSFan 1.4.4.1 extracted tree against current 2.8.0.1 assets
(`analysis/extracted/`, `analysis/recovered-reference/`, `analysis/catalogue/`):
added heroes (064–098 post-2019), added dialogue (DIALTU new files), UI_CSV help
revisions (Super Block 9%/5% history), LEVELING chunk diffs. List version-added
content with file paths + SHA where feasible. **No stat invention.**

Method: read-only. Directory listings, `Get-FileHash` (SHA-256), and the repo JET
decoder (`tools/jet-viewer/jet_decoder.py::inflate_jet_resources`) on in-memory
bytes with summary-only output (counts/kinds/short heads). No binaries committed,
no server/APK rebuild. Builds on `old-apk-2026-10-05.md` (APK audits) and
`local-reaudit-2026-10-05.md` (VSFan/LEVELING/EQUIP/phone-manifest/catalog
re-audit). No separate "old-apk lane" directory exists in this workspace; the
1.4.4.1 baseline is the VSFan tree
(`analysis/VSFan/Extracted Assets (2026)/1441 (APK)/`, APK held alongside it).

**Result up front: version-added content is art, audio, dialogue, help text, UI
strings and shared tuning. Zero per-hero / per-monster / per-item stat rows in
either version. No coverage credit changes** (heroes 1/113, accessories 1/100,
monsters 0/22). The one genuine numeric revision found is the in-game **jewel
set-bonus help table** (§4) — historical help text, not instance stats.

- 1.4.4.1: **KO shows 9%**, EN/JP/ZH/ZT show **5%** (KO `desc2` row 7 numeral

  So the old KO-vs-rest dispute is preserved inside 2.8.0.1 as an

Quarantine: help text only — set-bonus **definitions**, never per-item
instance values. Stays as historical set-bonus evidence (12/12 families, locale

## 9. Limits

- CJK text in both UI_CSV generations is mojibake under this tooling
  (EUC-KR/CP949 bytes read as CP1252/UTF-8); only ASCII numerals, IDs and EN
  strings are quoted. The KO 9% (old) readings rely on numeral position in
  row 7, consistent with the prior lane's decoded report.
- Old `LEVELING` bins and the old `LEVELING.jet` container were not decoded;
  even if they hold tuning, the 2.8.0.1 transcription shows this family carries
  shared modifiers, not per-entity rows.
- Throwaway decode output was kept in memory only; only this note was written.
