# Old-APK hunt for embedded stat tables (2026-10-05)

**Goal:** find downloadable old BLUSTONE APKs (`com.vshower.prd_sr`) and diff
their assets for card/monster/item numeric rows (HP/ATK/DEF, jewel/crystal).
**Result: negative.** No APK outside the current 2.8.0.1 base was downloaded
(all ~1 GB; binaries stay out of git per tasking), and every locally available
old package was audited read-only: **no per-hero, per-monster, or per-item stat
table exists in any of them.** Stat data was server-side (`/reference/*`); the
APKs carry art, audio, dialogue, help text, UI strings, and shared battle
tuning only.

## 2. Table audit — 1.4.4.1 APK (read-only, in-memory ZIP reads, nothing extracted)

APK ZIP: 877 entries, **52 `.jet` payloads** (full name/size list in §4).
Method: `tools/jet-viewer/jet_decoder.inflate_jet_resources` on in-memory
bytes + printable-text scan per resource for
`hp/attack/defense/stat/level/rank` keywords.

- **Character packs** C001/C003/C009/C010 (153–192 resources each),
  CE_PUB/CFE_PUB/CHA_AT/CI/CUTIN/SKE_PUB/WAG_PUB, **monster packs**
  M001/M002/M005/M006/M008/M009 (35–38 resources) and M100 (6): **zero text
  hits** — art/atlas/skeleton/audio only. No monster HP/ATK/DEF anywhere.
- **Effect/sound/font**: Cxxx_EFT/SND, INGAME_EFT, SND1, FONT, GLSL,
  MOTION, STORY_TUTO: 0 decodable text resources (opaque/binary containers).
- **Dialogue**: DIALTU-EN/JP/KO/ZH/ZT (11 resources each) = TalkerMaker
  conversation JSON (identity only, already mined).
- **Help/UI**: UI_CSV (5 resources, 4 text) = 157-record help corpus incl.
  `CONTENTS11_8` jewel set bonuses + `e44ab8ed.txt` UI strings + style/sound
  tables (already mined, no per-item rows).
- **Layouts**: LAYOUT-BASE opaque; LAYOUT-EN/JP/ZH/ZT single binary resources
  (the keyword "hits" there are binary false positives, not tables).
- **1.4.4.1 `LEVELING.jet` (57,962 B): 0 resources via this decoder** — a
  different container shape than 2.8.0.1's; the extracted tree keeps only two
  opaque bins (`6a434cb8.bin` 39 B, `6c1781a5.bin` 195 B). Not decoded, not
  claimed; even if it holds tuning, the 2.8.0.1 LEVELING (§3) shows this
  family carries shared modifiers, not per-entity rows.

## 5. Coverage impact

- Heroes 1/113, accessories 1/100, monsters 0/22: **unchanged**.
- No new numeric rows qualified for `polluted-observations.md` (the only
  numbers surfaced are shared tuning multipliers and card-referenced 1.1×
  stage buffs, neither attributable as a hero/monster/item stat row; they are
  recorded in §3 above with provenance instead).
- Positive side-effect: 1.4.4.1 vs 2.8.0.1 pack comparison shows per-version
  asset drift is real (e.g. LEVELING 58 KB vs 18.5 KB, LAYOUT split by locale
  in 1.4.4.1), so a future small-version download (e.g. QooApp 2.1.7.3 at
  108 MB) remains the cheapest next physical target — but expect the same
  server-side-data architecture, i.e. low prior for embedded stat tables.

## 6. Notes / limits

- No binaries downloaded or committed; all version metadata above is
  listing-page data. ApkHere per-build `/down/…` routes and APKCombo/Uptodown
  payloads were not fetched (each ~0.1–1 GB).
- Human-verification gates (APKPure EdgeOne, QooApp cards) were left
  untouched; no restriction bypassed.
- Throwaway decode scripts and text dumps from this pass were deleted, not
  committed; method is reproducible via `tools/jet-viewer/jet_decoder.py`
  (`inflate_jet_resources` takes bytes, strips the 6-byte `RW` header).
