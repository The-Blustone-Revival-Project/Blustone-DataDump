# Fight Club native-parser vs economy-table cross-check (2026-10-05)

**Scope:** cross-check the Namu-derived Fight Club economy tables in
`fc-economy-2026-10-05.md` (tier rewards Silver/Gold 100+2, Emerald/Metron
150+2, Mandarin 200+2; scoring +15/−8/−5~6; 31 rank bands; 255 anomaly;
Sunday settlement) against the recovered native Fight Club parsers
(`analysis/research/arena-battle-contract.md`,
`arena-lobby-contract.md`, `arena-my-rank-contract.md`,
`arena-season-time-units.md`, dumps `analysis/ghidra-arena-*`) and the
replica's arena sources (`server-ts/src/arena.ts`,
`server-ts/src/arena-service.ts`).
No HP/ATK/DEF base tuple here. No coverage-count change
(heroes 1/113, accessories 1/100, monsters 0/22). No server/APK change,
no implementation.

---

## 1. PURE — parser vs table agreement/gaps (values only, no provenance)

"Parser" = a natively recovered request/response key with a proved consumer
function. "Table" = a value from `fc-economy-2026-10-05.md` §§1.1–1.3.
A value "binds" only if the same parser key carries that table's quantity.
Nothing below binds.

### 1.1 Enter / season / profile parsers — no economy values involved

- `ReqEnterCB` (0xf5d3b4) → `ParseEnter` (0x942c3c) reads
  `ret_data.arena.status` (numeric 1 gates active parsing), `arena.season`
  (`ParseSeason`: season_no, weekly_no, start/end/next + weekly_start/end/next
  datetimes), `user.battle` (`ParseUser`: pvid, rank, season_no, weekly_no,
  league_level, rating_point, league_win, win, lose, refresh_datetime,
  start_message, win_message, lose_message), `user.is_weekly_reward`,
  optional root `ret_data.deck`.
- None of these keys carries fight chips, green manda, 고급 의뢰서, fuel
  coupons, or any ± scoring delta. The table's tier values (100/150/200 + 2),
  rank values (2500…100 + bonus), and scoring deltas (+15/−8/−5~6/−8) appear
  in **zero** recovered Enter literals.
- Verdict: **no agreement possible; gap is total** on this route.

### 1.2 FindRival / refresh_price — vocabulary mismatch

- `ReqFindOpponentCB` (0xf639a0) → `ParseFindRival` (0x947318) reads
  `ret_data.arena.rival_list[]` (ParseDefender records) and root
  `ret_data.refresh_price{price_type, price}`.
- The replica publishes `refresh_price = {price_type: 2, price: 100}` as an
  explicit local fixture (`arena-service.ts`).
- The FC tables have no `price_type`/`price` vocabulary: tier rows pay
  (chips, green manda), rank rows pay (chips + bonus). The numeral `100`
  recurs (Silver/Gold 100 chips; rank 4701–6100 … 100-chip rows; refresh
  fixture 100), but **no parser binds refresh price to any table row**, and
  `price_type: 2` has no table counterpart at all.
- Verdict: **gap** — same numeral, different unlinked fields. Do not equate.

### 1.3 Start resources / BP cost — cost magnitude unrecovered

- `ReqBattleWithCB` (0xf5dca8) → `ParseApBp` (0x943750) reads four FLAT
  scalars `user.ap`, `user.ap_charge_time`, `user.bp`, `user.bp_charge_time`
  (not prev/cur objects), then unconditionally SyncAP + SyncBP.
- No native BP-cost literal was recovered on this path; the replica charges
  BP 1 per accepted attempt as documented local policy (`ARENA_BP_COST = 1`).
- The FC tables quote no per-battle BP cost. Scoring deltas (+15/−8) are
  rating-direction numbers, not resource costs.
- Verdict: **gap** — cost value is fixture-only on both sides of nothing.

### 1.4 Complete result pairs — keys exist, table values do not bind

- `ReqBattleCompleteCB` (0xf5f174) → `ParseBattleResult` (0x944e68) reads
  `user.battle.{league_level, win, lose, league_win, rating_point}` and
  `user.honor`, every one a `{prev, cur}` pair; optional `user.free_iap` /
  `user.iap` `{prev, cur}` Manda pairs; `ret_data.card` map of decimal hunter
  serial → `{prev, cur}` absolute EXP. Complete does NOT call ParseApBp.
- The replica applies local win policy (rating +10, honor +10; loss rating
  −10) and zero hunter EXP — all marked fixtures.
- Table scoring (+15 win / −8 loss / −5~6 defense loss / −8 revenge-loss /
  forfeit) is unattributed to any named parser key in the native evidence:
  the parser key is `rating_point`, the table never names `rating_point`,
  and no decomp maps win/loss deltas to ±15/±8. The `honor` pair exists
  natively, but the tables award no per-battle honor amount to bind to it
  (honor appears only as a zero-valued league/weekly reference field).
- Verdict: **structural seam only** (pairs exist; deltas exist); **no value
  binds**. Do not set rating ±15/∓8 or honor awards from the table.

### 1.5 League / weekly reference rows — key-shape match, all-zero values

- `ReqBattleLeagueCB` (0xf83a38) → `ParseBattleLeague` (0x948438) /
  `ParseBattleWeeklyRwd` (0x948b48) read `ret_data.league[]`
  (`league_level, max_win, user_exp, gold, free_iap, iap, honor,
  item_list[]{id, qty}`) and `ret_data.weekly_reward[]`
  (`min_ranking, max_ranking, user_exp, gold, honor, free_iap`, same
  item_list). This is the sole native table shaped like a reward catalog.
- The replica publishes 6 league rows (`max_win: 6`, all rewards 0) and 1
  weekly row (rank 1–999999, all rewards 0) — explicit fixtures.
- The FC rank table's 31 bands (ranks 1–30000+, chips 2500…100 + bonus)
  share only the *idea* of rank bands with `min_ranking`/`max_ranking`; every
  native reward cell the parser actually reads (user_exp, gold, honor,
  free_iap, iap, item_list) is 0/empty in the replica and has **no nonzero
  table value under the same key name**. Bonus currencies (green manda,
  고급 의뢰서, fuel coupons) have no key in either reference row.
- Verdict: **key-shape seam confirmed, value agreement zero**. The 31-band
  table cannot populate these rows without inventing key mappings.

### 1.6 The two sixes — numeric coincidence, not corroboration

- Native `max_win: 6` (league reference row key) and table tier-up rule
  (6 wins per tier regardless of losses; 6 league wins per local league in
  the replica) share the numeral 6 across three different containers
  (reference row, wiki tier rule, local league policy).
- No parser derives tier progression from `max_win`, and no table names
  `max_win` or `league_win`.
- Verdict: **coincidence preserved, binding refused**.

### 1.7 Season timing / Sunday settlement — units yes, schedule no

- `ParseSeason` stores six datetime fields numeric64; `RemainTimeTextRenewal`
  subtracts `GetCurServerTime` (seconds) and divides by 86400 — end_datetime
  seconds proved (`arena-season-time-units.md`). The replica's week-aligned
  Unix-second season is unit-correct, schedule-fixture.
- No native literal names Sunday, settlement, reset, or payout-timing. Both
  Namu-derived sources agree on "settlement + reset every Sunday; payout
  after settlement only" — with zero native corroboration.
- Verdict: **clock units agree with the replica; weekly schedule is gap**.

### 1.8 GetMyRank scalar vs rank bands — different things

- `ReqMyRankCB` (0xf600d8) reads scalar `ret_data.rank` → PlayData+0x128;
  replica returns rank 1 (single-player fixture).
- The 31 table bands are *reward* bands keyed by rank range, not a value of
  this scalar. No binding exists between scalar rank 1 and the rank-1 reward
  row (2500 + 800).
- Verdict: **gap**.

### 1.9 Bid / revenge / friendship — no table prices

- Start request carries `target_pvid, is_revenge, is_friendship, bid`
  (uint64 decimals + 0/1 flags); Complete carries `target_pvid, is_revenge`
  + `play_info` string (`is_win`, clear_time, dead_cnt, HP pairs, atk_max,
  atk_total, atk_cnt). No returned bid/completion nonce is consumed by any
  inspected Start parser.
- The tables quote no bid price, revenge cost, or friendship charge.
- Verdict: **gap**.

### 1.10 Cross-check verdict (pure)

| Native parser surface | Table candidate | Result |
|---|---|---|
| Enter/season/profile/deck keys | any tier/rank/score value | no key overlap — gap |
| refresh_price{price_type, price} | 100-chip rows | numeral recurs, fields unlinked — gap |
| ParseApBp flat scalars / BP cost | per-battle cost | cost unrecovered — gap |
| Complete battle/honor/Manda pairs + card EXP map | +15/−8/−5~6, honor, hunter EXP | keys exist, values unbound — gap |
| league[]/weekly_reward[] reference keys | 31 rank bands | shape seam only, values zero — gap |
| max_win 6 | 6-win tier-up | coincidence — refused |
| end_datetime seconds | Sunday settlement | units only — schedule gap |
| GetMyRank scalar | rank-1 reward row | different things — gap |
| bid/revenge/friendship | any price | no table price — gap |

**Bottom line:** the parsers prove *where* Fight Club economy values would
land (Complete pairs, league/weekly reference rows, refresh_price); the
tables supply *candidate* economy values under *different* names with no
recovered key mapping. **Zero value-level agreements; nine documented gaps.**
The replica's BP 1, rating ±10, honor +10, six-wins-per-league, rank 1,
refresh 100/type 2, and all-zero reference rewards remain labeled local
fixtures, unaffected by this cross-check.
